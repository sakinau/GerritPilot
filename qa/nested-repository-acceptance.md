# 嵌套仓库隔离验收（待构建）

仅在临时父/子 Git 仓库中验证；不要用真实 HMI 改动进行丢弃或提交试验。

1. 父仓库包含普通修改和嵌套 component、framework 仓库。嵌套仓库分别使用 `.git` 目录、`gitdir:` 文件（worktree/repo 形式）。父仓库 Changes、数量、单文件 Diff、整个工作区 Diff 只显示普通修改。
2. 嵌套仓库内存在修改、未跟踪文件时，切到该子仓库仍能正常显示；不按 component/framework 名称硬编码，普通同名目录应正常显示。
3. “暂存全部”只操作父仓库自身文件。提交、取消暂存、块级操作、标记冲突解决不能对嵌套路径操作。传入 `.`、绝对路径、`../` 或非状态列表路径应被拒绝。
4. 预先在临时父仓库暂存一个 gitlink，然后另有普通文件可提交。提交前置检查应报错并取消该操作的后续 commit/push，不自动移除 gitlink 或清空用户暂存。
5. 设置 Git `ignoreSubmodules=all` 后重试第 4 项，前置检查仍应拒绝。删除工作区子仓目录后，已暂存的 gitlink 删除仍应被识别。
6. 正常父仓库普通提交、amend、重命名、带空格/中文的文件不被误过滤；只含嵌套改动时整仓 Diff 为空，不退回无路径限制的 `git diff`。
7. 加载旧缓存不重新显示被过滤的文件或详情文本。刷新后仓库数量与过滤后的文件列表一致。

实现边界：工作区提交隔离，不改写已有历史，不删除 `.git`、不修改 `.gitignore`、不自动取消已有暂存。正式 submodule 的 gitlink 更新也被视为跨仓库修改而排除；有意维护父仓库 submodule 引用时需在外部 Git 工具中操作。
